# Ukraine–Russia war data for a graph-focused course project

Research note, 27 October 2026. The goal is a small, reproducible study with an edge that has a defensible meaning. A reported-event pattern can describe *documented combat activity*; it cannot alone identify operational intent, tactical effectiveness, or why one side chose a tactic.

## Feasibility judgment

There is no clear public option that simultaneously offers **easy download, rich observed tactical edges, and defensible conclusions about battlefield tactics**. The most direct actor-interaction data are ACLED's event records, but access is conditional. The easiest freely downloadable war data are UCDP GED and VIINA; their Ukraine subsets are principally event tables, so a graph of places or tactic categories would require constructing edges that were not observed.

## Closest bounded project, if ACLED access works

**Question:** “In documented armed-clash events in one Ukrainian oblast and one defined period, how concentrated are interactions among named actors compared with a graph that preserves each actor's observed number of interactions?” Use only `Battles` / `Armed clash` events with two identifiable actors. Treat edges as undirected, since ACLED says actor order does not establish aggressor. Inspect distinct actor count and degree distribution before committing: if the result is a single Ukraine–Russia edge with a few aliases, abandon the graph framing. A tactical statement would be limited to **the composition and geography of reported clashes**, not battlefield effectiveness.

If event-level ACLED access is unavailable or this graph is degenerate, the candid recommendation is to choose between (a) a **VIINA tactics and geography** project without insisting on graph methods and (b) a **graph-first project about wartime physical infrastructure** that accepts much more data preparation. There is no honest shortcut from event locations or shared article dates to troop routes or successful tactics.

## Simpler war-specific graph: territorial connectivity

[VIINA's own release](https://github.com/zhukovyuri/VIINA/blob/main/README.md) also provides daily settlement-level territorial-control status and tessellated settlement polygons. In a single region and short campaign window, define a spatial graph with one node per populated place and an edge where the supplied polygons share a boundary. Color each node by the dataset's reported controller. A bounded question is: **How did the size and number of connected Russian-controlled areas change during the September 2022 Kharkiv counteroffensive?** Compare observed component changes with a baseline that removes the same number of settlements from the previous day's control boundary. First check map-update dates, missing statuses, geometry joins, and whether apparent isolated pockets persist across source versions.

This graph represents geographic neighborhood, not roads, supply flow or observed troop movement. It can describe the topology of reported territorial change, but cannot establish why the counteroffensive succeeded or which battlefield tactic caused a change. It is a more tractable network project than matching sparse reported bridge strikes to a transport network: the inspected Militarnyi export contains only 23 rows explicitly labeled road or railroad bridge, spread across eight regions (six in Crimea).
