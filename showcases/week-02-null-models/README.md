# Marvel Lineup

A self-contained static Week 2 puzzle. Open this directory through the existing
GitHub Pages site or a local HTTP server. No build, account, backend, or package
installation is required. All implementation files stay in this folder.

From the repository root, run `python -m http.server 8000` and visit
`http://localhost:8000/showcases/week-02-null-models/`.

## Playing

Each of three fixed puzzles contains eight predictions:

1. Insert three hero cards into a lineup ordered by degree. Two anchors start revealed.
2. Insert three cards into a new lineup ordered by local clustering, using complete
   small neighborhood diagrams as clues.
3. Predict whether the degree ranking survives degree-preserving shuffling, then
   predict how the entire network's average clustering compares after 100 shuffles.

Each correct prediction earns 100 points, with no time bonus or penalty for taking
longer. Incorrect cards are inserted at their correct position before continuing.
Equal values, if introduced in future data, accept either equivalent insertion slot.
Players can replay or move through the three puzzles after finishing.

Names are optional after scoring. The leaderboard uses localStorage, is explicitly
browser-local, and is separate for each puzzle. It keeps the top 50 submissions per
puzzle and displays the top 10; earlier submissions win ties. A completed run can
only be saved once. Clearing site data removes scores. Storage failures leave the
result available and let the player retry. This is a casual client-side leaderboard;
it provides no verification against someone editing their own browser data.

## Data and curriculum

`prepare_data.py` reads `../../data/week1/week1_nodes.tsv` and `week1_edges.tsv`.
The frozen source has 303 Wikipedia articles and 1,784 directed hyperlinks. Either
hyperlink direction produces one undirected edge; reciprocated links are deduplicated.
This yields 1,434 edges and 17 isolates. A hyperlink is not a canonical Marvel alliance.

The degree sketches show all neighbors but omit links between neighbors. Clustering
sketches show every neighbor and every link between those neighbors. Hero names come
from the source; generic parenthetical disambiguators are omitted on cards. The player
does not need to know Marvel lore: the visible sketches provide the evidence.

Local clustering is `2e / (k(k-1))`, where `e` counts links among the `k` neighbors;
degree below two contributes zero. The null test averages this quantity over **all
303 nodes**, including isolates. This differs from the curriculum's giant-component
example, so its published values are not hard-coded into the game.

The generator uses Python's seeded RNG (`2805`) and creates 100 shuffles, each
restarting from the original simple graph and accepting `10 × 1,434` double-edge
swaps. It rejects self-loops, duplicate edges, and swaps without four distinct
endpoints. It verifies each individual node's degree remains unchanged. Ten swaps
per edge is a practical mixing heuristic, not a proof of perfectly independent,
uniform samples. The last shuffled graph supplies the before/after neighborhood
example. The checked-in distribution is precomputed, not generated by the animation.

The one-sided empirical p-value is `(1 + count(shuffled >= real)) / 101`; it is never
reported as zero. The comparison concerns network clustering, not player skill or
game scores. Surplus clustering relative to this null supports structure beyond
the degree sequence, without identifying the mechanism that created it.

Curriculum focus: degree/hubs, local clustering, and choosing a degree-preserving
null model. The game does not simulate preferential attachment or teach the complete
Week 2 curriculum. It uses no fabricated hero attributes or Marvel artwork.

## Rebuild and verify

From this folder:

```sh
python prepare_data.py
python -m unittest test_data.py
node --test game.test.mjs
node --check app.mjs
```

Commit `puzzle-data.json` with any generator changes. It includes the input SHA-256,
all displayed measurements, the three decks, and all 100 null samples. Python uses
only its standard library. The UI uses browser-native ES modules and SVG. Google
Fonts enhance the typography; system/Georgia fallbacks work when fonts are unavailable.
