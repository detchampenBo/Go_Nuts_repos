# Art direction

Make a design specific to its subject and its user's taste. A genre label such as “comic book” is a starting point for investigation, not a ready-made palette or layout. User instructions and accepted design decisions take precedence over this workflow.

## Establish the brief

Identify the experience, audience, core interaction, and what the user has accepted or rejected. Inspect the current work before proposing a replacement. Preserve useful functionality and the user's accepted visual choices. Separate dissatisfaction with styling from dissatisfaction with the interaction.

Write a short working brief: what the user should understand or feel, what must remain, and what needs to become distinctive. Use available context; ask only for consequential missing information.

## Study references

Before committing to a new direction, inspect a small set of concrete visual references, typically three. Prefer user-provided examples and original work by artists, studios, museums, or product creators. Include an adjacent medium when useful: stage design, animation frames, physical games, exhibition graphics, maps, or book design.

For each reference, record its source and a specific transferable observation: composition, spatial hierarchy, character treatment, material, typography, or the way motion communicates meaning. Distinguish what was actually inspected from an imagined concept. If access is unavailable, disclose the gap and continue with available material; do not fabricate research.

Translate observations into design decisions rather than copying a complete composition. Research references do not automatically become licensed assets for reuse.

## Compare concepts before implementation

For an open visual brief, sketch three directions. Each should differ in at least two structural dimensions: layout, navigation, representation of information, interaction, or asset treatment. Palette swaps of the same card grid are one concept.

For each direction, give a compact sketch or storyboard, its central visual idea, the user's main action, and a practical tradeoff. Avoid building three finished applications. If the user has already selected a direction, develop that choice instead of reopening the decision.

Name a short, project-specific list of defaults to move beyond and pair each with a positive alternative. Rejected motifs are local evidence, not universal prohibitions. For example, a superhero project might replace repeated neon cards with characters participating directly in an evidence scene. Do not turn that example into the default for every project.

Recommend the direction that best joins subject, interaction, and readability. If implementation is authorized, proceed using the user's preferences and explain the choice; this skill does not introduce an approval gate.

## Make the visual idea carry meaning

State what each prominent visual element communicates. For educational work, the interaction should reveal the concept itself: distance through successive discovery, influence through accumulation, or comparison through a shared scale. Preserve correct quantities and clear legends; novelty must not distort the explanation.

Choose typography, colour, assets, and motion to support the concept. Character-led work needs an intentional portrait and expression system; a token icon or a generic silhouette is not automatically sufficient. Use generated raster art, original vectors, or available assets according to the desired visual result and available tools, not whichever format is easiest to code.

Keep a brief record of the selected direction and its reasons with the prototype or existing design notes. Reuse it during revisions so each turn does not reset to a genre stereotype.

## Critique the rendered result

Inspect the actual composition at desktop and narrow widths when rendering tools are available. Compare it with the working brief and reference observations. If rendering is blocked, say which checks remain unverified rather than claiming visual validation.

Ask:
- If the title and colours changed, could this be any unrelated dashboard?
- Does the main interaction embody the idea, or is the theme only decoration?
- Are the characters or assets visually specific enough to carry the experience?
- Can a new user identify the next action without an explanation from the developer?
- Does the result repeat motifs the user already rejected?

Revise the largest mismatch first. Change composition or interaction when that is the problem; extra decoration will not fix it. Report concrete changes and remaining uncertainties. Treat distinctiveness as a design judgment to evaluate with the user, not a guaranteed property conferred by this skill.
